# 一键排版分段快捷按钮设计

## 理解摘要

- 在写作面板中把现有大号“一键排版”入口拆成“直接执行 + 设置”两个相邻操作。
- 主按钮直接使用上次保存的一键排版方案，不再打开设置窗口或要求二次确认。
- 当前编辑器存在选区时只处理选区；没有选区时处理整篇笔记。
- 设置按钮继续打开现有“一键排版”窗口，用于选择和调整默认方案。
- 执行后继续提供结果提示，并支持通过 `Ctrl+Z` 撤销正文修改。
- 可选择显示一个独立的 Obsidian Ribbon 魔法棒按钮，直接执行同一套默认方案。
- 可选择在用户手动把当前笔记从关闭切换为写作模式时自动执行一次默认方案。
- 修复右侧工作台首次被激活时重绘自身、导致第一次按钮点击丢失的问题。
- 不新增批量排版行为，不修改阅读视图；仅增加两个默认关闭的布尔设置字段。

## 目标与非目标

### 目标

- 把高频的一键排版操作缩短为一次点击。
- 复用已经保存的排版方案、规则顺序和 Markdown 处理方式。
- 保持现有选区、光标、滚动恢复、结果提示和撤销体验。
- 让直接执行与方案设置在视觉上保持为一个整体，同时具备清晰的键盘和无障碍语义。

### 非目标

- 不改变排版算法或内置方案内容。
- 不增加新的确认弹窗、范围选择弹窗或批量处理入口。
- 不改变命令面板和编辑器右键菜单中现有的“一键排版…”行为。
- 不修改插件版本号或阅读视图实验代码。
- 不让自动规则、全局默认或打开已有写作笔记静默触发正文排版。

## 假设与非功能要求

- 性能：只处理当前编辑器中的选区或单篇文本，继续使用现有同步文本转换管线。
- 规模：本功能不处理多文件；多文件仍由现有批量排版功能负责。
- 隐私与安全：所有文本和设置保持本地，不增加网络请求或外部服务。
- 可靠性：一次点击使用同一份设置快照；执行期间禁用主按钮，避免快速双击重复处理。
- 可靠性：自动排版失败不会回滚已经开启的写作模式；两者保持独立。
- 可恢复性：正文修改继续进入编辑器撤销历史，用户可使用 `Ctrl+Z` 撤销。
- 可维护性：复用现有 `applyFormatting()`，不复制排版算法；新增字段使用布尔默认值，不推进设置 schema。
- 可访问性：两个操作使用独立的原生按钮，具备标题、无障碍标签、键盘焦点和足够的移动端点击区域。

## 方案比较

### 方案 A：两个真实按钮组成分段控件（采用）

外层容器负责统一边框和布局；左侧主按钮直接执行，右侧图标按钮打开设置。该方案语义清楚、键盘和无障碍支持完整，也最容易进行自动化验证。

### 方案 B：单按钮内部划分点击区域

DOM 改动较少，但键盘无法自然选择两个操作，点击区域判断容易变得脆弱，不采用。

### 方案 C：执行和设置分别放在面板不同区域

实现简单，但破坏操作的关联性，用户不容易理解设置入口控制的是哪一个快捷动作，不采用。

## 最终设计

### 界面结构

现有 `renderFormattingLauncher()` 改为渲染一个分段控件：

- 左侧主按钮保留魔法棒图标和“一键排版”标题，说明文字为“使用当前默认方案，支持撤销”。
- 右侧设置按钮使用设置类图标，`aria-label` 和 `title` 为“设置一键排版方案”。
- 两个按钮均为独立的 `<button type="button">`，由共享容器呈现为一个完整入口。

### 执行链路

主按钮调用插件公开入口 `applySavedFormatting(editor?)`：

1. 获取传入编辑器或当前 Markdown 编辑器。
2. 找不到编辑器时显示提示并安全返回。
3. 读取当前保存的 `formattingPreset`、`formattingRules`、`formattingRuleOrder` 和 `markdownFormatting` 快照。
4. 调用现有 `applyFormatting()`，并设置为不重复保存默认值。
5. 沿用现有选区优先、整篇回退、光标与滚动恢复、结果提示和撤销行为。

设置按钮继续调用 `openFormattingModal()`。命令面板和右键菜单行为保持不变。

### 可选 Ribbon 快捷按钮

- 插件加载时创建一次独立的 `wand-sparkles` Ribbon 图标，并保存元素引用。
- `showQuickFormattingRibbon` 控制按钮显示，默认值为 `false`。
- 设置页切换后立即同步显示状态，无需重载插件。
- 点击后调用统一的 `applySavedFormatting()`，行为与工作台主按钮一致。

### 手动开启写作模式时自动排版

- `autoFormatOnManualWritingMode` 控制该行为，默认值为 `false`。
- 仅当 `toggleNovelMode()` 检测到当前笔记发生“关闭 → 开启”时执行。
- 自动规则、全局默认、打开已经处于写作模式的笔记，以及简洁版切换专业版均不触发。
- 自动排版失败时保留已开启的写作模式，并单独提示失败。

### 首次点击修复

当前 `active-leaf-change` 会在右侧 `WritingPanelView` 首次被激活时立即调用
`refreshWritingPanels()`。这会在浏览器完成点击序列之前清空并重建按钮 DOM，导致第一次
`click` 丢失。激活叶片本身是 `WritingPanelView` 时跳过这次即时重绘；状态同步和延迟统计
更新继续保留。

### 异常处理

- 文本已经符合规则时沿用现有提示，不产生无意义的编辑记录。
- 主按钮在 Promise 完成前保持禁用，并在成功或失败后恢复。
- 意外异常记录到控制台，并通过 Notice 告知用户“排版失败，请重试”。
- 不主动覆盖或回滚用户其它未提交修改。
- 两个新增设置缺失或不是布尔值时均回退为 `false`。

## 测试策略

按照 TDD 顺序执行：

1. 先添加失败测试，验证分段控件、两个按钮及其调用关系。
2. 添加执行入口测试，验证完整复用已保存设置且不重复保存默认值。
3. 添加 Ribbon 测试，验证默认隐藏、即时同步和统一执行入口。
4. 添加写作模式转换测试，验证只有手动“关闭 → 开启”触发自动排版。
5. 添加工作台首次激活回归测试，验证侧栏不会在点击序列中重绘自身。
6. 验证没有编辑器时安全返回。
7. 实现最小代码使测试通过。
8. 运行相关测试、完整测试套件与生产构建。

## 决策记录

- 入口形式：选择“直接执行 + 设置”的分段控件。
- 处理范围：选区优先，没有选区时处理整篇。
- 确认策略：直接执行不弹确认窗口。
- 撤销策略：继续使用编辑器原生撤销历史。
- 组件语义：使用两个真实按钮，不使用单按钮点击区域判断。
- 数据策略：复用现有排版设置；仅新增两个默认关闭的布尔字段，不推进 schema。
- 并发策略：执行期间禁用主按钮，避免重复点击。
- 代码边界：复用现有 `applyFormatting()`，不改排版算法、批量排版或阅读视图。
- Ribbon 策略：新增独立图标，默认隐藏，通过设置即时显示或隐藏。
- 自动触发策略：只响应用户手动把当前笔记从关闭切换为开启。
- 故障隔离：自动排版失败不回滚写作模式。
- 首次点击修复：工作台激活自身时不立即重绘自身。
