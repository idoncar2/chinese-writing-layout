# 正文“滚动到底部”悬钮设计

## 理解摘要

- 在 Markdown 正文编辑区提供一个一键滚动到当前笔记底部的悬浮按钮。
- 解决长文档需要反复拖动滚动条、滚轮或触控板的问题。
- 按钮只改变编辑器滚动位置，不移动光标、选区或编辑焦点。
- 每个编辑窗格独立工作，分屏和多标签页之间不共享滚动状态。
- 正文不可滚动或已经接近底部时隐藏，向上滚动后重新出现。
- 不扩展到阅读视图、侧边栏或设置弹窗，也不新增设置项。

## 假设与非功能要求

- 目标平台包括 Obsidian 桌面端和移动端的 Markdown 编辑器。
- 滚动监听只读取当前编辑器的尺寸和位置，不读取或保存正文内容。
- 状态更新应保持轻量，每个编辑器实例只绑定一个滚动监听器。
- 编辑器卸载时必须移除按钮和监听器，避免残留 DOM 或内存泄漏。
- 默认平滑滚动；系统启用 `prefers-reduced-motion: reduce` 时即时到达。
- 使用 Obsidian 原生图标及语义颜色变量，兼容深色、浅色和第三方主题。

## 方案比较

### A. 编辑器实例内的 CodeMirror ViewPlugin（采用）

每个 Markdown 编辑器实例创建自己的悬钮，直接监听其 `scrollDOM`。定位和状态天然属于对应窗格，分屏时不会串位，销毁生命周期也由 CodeMirror 管理。

### B. 工作区级统一悬钮

插件创建一个按钮并跟随当前活动叶子。代码入口集中，但必须处理活动窗格切换、分屏定位和工作区重排，容易短暂显示在错误位置。

选择方案 A，因为按钮是正文编辑器自身的导航控件，生命周期和滚动容器都应保持局部化。

## 最终交互

1. 编辑器挂载后创建一个带向下箭头的原生 `button`。
2. 当 `scrollHeight > clientHeight` 且距离底部超过约 40px 时显示。
3. 点击时调用当前 `scrollDOM.scrollTo`，目标为其最大滚动位置。
4. 不调用 selection、dispatch 或 focus API，保证光标与选区不变。
5. 到达底部后隐藏；用户再次向上滚动超过阈值后显示。
6. 按钮提供“滚动到正文底部”的可访问名称和可见键盘焦点。
7. 使用透明度与位移做轻微显隐，不改变正文布局；减少动态效果时取消过渡和平滑滚动。

## 视觉约束

- 小型圆形悬钮，视觉图标与 Obsidian 的 Lucide 图标体系一致。
- 点击区域满足至少 32px 的桌面使用尺寸；移动端通过媒体条件扩大到 44px。
- 位于正文右下角并避开滚动条、状态栏和移动端安全区域。
- 使用 `--background-primary`、`--text-muted`、`--interactive-accent` 等语义变量，不写死明暗颜色。
- 隐藏状态不能接收鼠标或键盘事件。

## 测试策略

- 短文档不显示，长文档顶部显示。
- 距底部阈值内隐藏，向上滚动后恢复。
- 点击目标是当前编辑器的最大滚动位置。
- 点击前后选区保持不变。
- `prefers-reduced-motion` 分别选择 `smooth` 和 `auto`。
- 两个编辑器实例拥有独立按钮和状态，销毁后移除监听器。
- 样式使用主题变量，具有焦点状态、移动端尺寸和减少动态效果规则。
