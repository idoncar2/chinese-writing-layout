# 当前开发状态

## 本次完成

- 发布 `1.0.3`：右侧工作台新增默认方案一键排版、独立撤回与设置入口；可选 Ribbon 按钮默认关闭并在启用后追加到末位；支持手动开启写作模式时按设置自动排版。
- 修复右侧工作台首次点击失效；一键排版设置改为只保存默认规则，版式恢复改为恢复当前选中模板；实验性阅读视图继续关闭。
- 修复全局已保存模板 ID 与顶层版式缓存分叉时显示成 Obsidian 默认样式：已保存模板快照改为全局渲染权威数据源，继续微调时明确转为自定义版式。
- 收敛打字机模式入口：设置项改为控制工作台按钮是否作用于所有文章；关闭时按文章保存状态，开启时维持原有全局行为，且两种作用域均可脱离写作模式使用。光标定位机制保持不变。
- 在工作台当前笔记区域增加可点击的“版式来源”状态，区分全局默认、自动规则、Obsidian 与当前笔记独立版式；点击后定位并强调版式微调中的唯一独立版式开关。
- 新增与 Writing Calendar 兼容的工作区自动套用规则只读 API：复用现有 `autoApplyRules` 的文件夹、标签、文件名和 CSS Class 匹配条件，保持规则顺序，不暴露私有设置对象；规则变化通过订阅通知消费者，模块注册/卸载通过全局生命周期事件通知。

- 插件版本已推进至 `1.0.0`，先作为私人仓库正式候选发布，不同步公开仓库。
- 完成 v1 发布审查：刷新 README、安装指南与人工验收清单，修正 manifest 描述格式。
- 删除打开文件夹时用于抢焦点的 PowerShell / `child_process` 实现；桌面端仍通过受平台保护的 Electron `shell.openPath()` 打开系统文件夹。
- 移动端保留 TXT、Markdown、DOCX 和 PNG 导出，固定写入当前仓库根目录的 `写作导出/`；自定义系统保存位置、打开当前文件所在文件夹和打开最近导出文件夹入口明确置灰，内容预览与复制全文继续可用。
- 完成当前文件与完整 Git 历史的公开化扫描；未发现被跟踪的 Vault 路径、部署配置、`data.json`、字体文件、Token、日志或发布 ZIP。旧提交历史包含非 noreply 邮箱，未来公开仓库应使用干净的 v1 初始提交，不直接镜像私库历史。
- 完成长图导出第一批：可选输出宽度、排版分图计划、分图预览、逐张渲染、统一命名和失败提示。
- 导出图片直接写入本地文件系统；Obsidian 文件列表不再创建中间导出文件夹。
- 完成写作模式、自动套用规则、标题居中、历史版本入口、设置页保存队列和初始 Markdown 页面识别等回归修复。
- 新增 Issue 1 字体数据模型：`FontSelection`、`UserFont`、`bodyFont`、`headingFont`、`quoteFont`、`boldFont`、`italicFont`。
- 新增 schema 2 字体迁移与兼容层：旧 CSS 字体字符串取第一个实际字体名称；特殊字体默认跟随正文；缺失的用户字体引用保留并仅在运行时安全降级。
- 全局版式、保存模板和单篇版式均可读写新的字体字段，同时保留旧 CSS 字段供当前渲染器兼容。
- Issue 5 已清理旧字体组合、字体排序、后备字体设置、系统字体扫描及相关过时代码；旧 `customFontPresets` 只保留一次性数据清理兼容，不再进入设置模型。
- 完成 Issue 2 精确字体选择器：按“跟随 Obsidian / 内置字体 / 我的字体 / 系统字体”分组，选择后立即应用。
- 设置页和写作工坊已接入结构化字体选择；“跟随 Obsidian”显示为“默认”，特殊格式支持“跟随正文”。
- 切回“跟随 Obsidian”时会清理旧的结构化与 legacy CSS 字体覆盖，避免界面显示与实际字体不一致。
- 完成 Issue 3 用户字体导入：支持 `.ttf`、`.otf`、`.woff`、`.woff2`，字体文件保存到插件目录，`data.json` 只保存元数据。
- 用户字体会在插件启动时注册为运行时 `@font-face`；文件暂时缺失时保留原引用并显示提示，导入、重命名、删除均会同步刷新设置页与写作工坊。
- 删除用户字体前会显示引用数量，并按正文/标题回到“跟随 Obsidian”、特殊格式回到“跟随正文”的规则修复引用。
- 字体选择器增加四个“快捷字体”（宋体、黑体、楷体、仿宋），只检测少量跨平台候选名称，不扫描系统字体；未找到时显示不可用并建议导入字体。
- 推荐写作版式会先解析已知字体候选；首选字体不可用时改用当前 Obsidian 暴露的实际字体名称，避免界面仍显示“思源宋体/思源黑体”而页面使用其他回退字体。
- 增加折叠式“如何添加字体？”说明，保留 `builtin` 数据源作为底层兼容结构，但本轮不显示、不打包内置字体文件。
- 优化快捷字体四项卡片的对齐：统一网格间距与最小行高，卡片内容顶部对齐，并缩短设备可用性说明，避免换行造成视觉错位。
- 修复 Android WebView 将不存在的快捷字体全部误判为“当前设备可用”的问题：候选字体现在必须通过实际渲染宽度对比；用户导入字体改为直接读取二进制注册，不再依赖桌面式资源 URL。
- 明确快捷/系统字体会随设备变化；从正文、标题或特殊格式选择器导入用户字体后，会立即选中并应用该字体，避免移动端仍停留在桌面系统字体引用并回退到手机默认字体。
- 修复写作工坊连续刷新后可能无法正常上下滚动的问题：取消旧滚动恢复任务时同步清理状态，用户向上滚动不再被历史位置覆盖，并补齐移动端滚动容器约束。
- 修正 v1 候选的移动端导出边界：不再禁用整个导出按钮，移动端恢复四种格式导出并沿用仓库内 `写作导出/` 的安全写入方式；仅桌面系统文件夹选择与打开操作不可用。
- 修复移动端长图沿用电脑宽屏排版导致文字过小的问题：移动端使用稳定的 360px 手机阅读宽度进行换行和字号布局，再按所选 1080/1440/2160 输出宽度等比放大；分辨率只影响清晰度，不改变手机端每行字数，也不依赖移动 WebView 的视口 API。
- 删除旧字体组合模块、旧字体选择器样式和对应测试；保留旧 CSS 字符串迁移所需的单字体解析工具。
- 修复自定义/推荐版式的标题字体在编辑视图与阅读视图间切换时不一致的问题：插件现在同时同步 Obsidian 的笔记内联标题变量 `--inline-title-font` 与 `--h1-font` 至 `--h6-font`，覆盖笔记标题、CodeMirror 内层标题文本和阅读视图标题，并保留纯“跟随 Obsidian”模式的原生主题行为。
- 将用户导入字体从插件安装目录迁移到 Obsidian 配置目录下独立的 `chinese-writing-layout/fonts/`，避免移动端或社区插件更新替换用户字体；旧目录会优先安全迁移，失败时继续回退读取旧文件。
- 字体迁移会校验复制后的二进制内容，无法验证的新副本会移除并保留旧文件，避免更新过程中损坏用户字体。
- 收紧“我的字体”界面：字体信息、选择状态和管理操作整合为紧凑卡片，长文件名省略显示并保留完整提示，移动端保持可用触控区域。
- 修正字体名称展示歧义：系统别名显示为“系统默认字体”，思源字体标明“优先使用”，快捷字体同时显示中文分类和当前设备候选名称，不再把 CSS 请求名称表述成已确认的实际渲染字体。
