# 中文引号统一修复设计

## 目标

把一键排版中分散的中文引号处理统一为可预测、可重复执行的流水线，重点解决：

- 成对引号方向写反，例如 `”一年之计在于春“`、`“一年之计在于春“`。
- 连续输入两三个同类引号，例如 `“”“`、`““”`、`””`。
- 只有一边引号时，可按用户选择采用保守或按段落补全。
- 合法嵌套引号、Markdown 结构和代码内容不被误改。
- 设置界面不常驻冗长说明，只在两个补全选项旁按需显示帮助。

## 已确认的理解

- “修复引号方向”负责已有引号的方向与明显重复问题，默认开启。
- “保守补全”和“按段落补全（宽松）”只负责缺少一边的情况，互斥且默认关闭。
- 一键排版仍是显式改写 Markdown 的操作，并继续使用现有整篇撤销能力。
- 不把所有相邻引号粗暴压缩；能判断为合法嵌套或上下文不明确时保持原文。

## 考虑过的方案

1. 继续给每个案例增加正则。改动小，但规则顺序互相影响，无法稳定处理跨行、嵌套和连续引号。
2. 仅按段落交替指定开、闭方向。实现简单，但会把合法跨段引语和复杂嵌套误判。
3. 建立统一分析流水线。先保护 Markdown 非正文区域，再对可编辑文本做局部连续引号归一、成对分析、方向修复和可选补全。

采用方案 3。它比继续叠加特殊判断更容易测试，也能保证多次运行结果一致。

## 处理顺序

1. 由现有排版规则先完成用户选择的引号样式转换。
2. 标记 YAML、代码块、行内代码和 Markdown 链接目标等不可改区域。
3. 清理明显的连续同类引号：
   - `““文字”` → `“文字”`
   - `“文字””` → `“文字”`
   - `“”“`、`““”`、`””` → `“”`
4. 重新扫描引号，按单双引号分别分析，并修复能确定的成对方向：
   - `”文字“`、`“文字“` → `“文字”`
   - 合法的 `“他说：‘你好。’”` 保持不变。
5. 如果启用了补全，再执行且只执行一种模式：
   - 保守补全：仅处理带中文冒号、单一明确对白、无复杂嵌套的缺边情况。
   - 按段落补全：段落中只有一个明确未配对引号时，在段首或段尾补齐。
6. 最后重新校验；仍不确定的内容保留原文，不猜测改写。

## 界面

- 删除四个相关选项下面常驻的小字说明。
- 仅“保守补全”和“按段落补全（宽松）”旁显示一个小型问号按钮。
- 问号可悬停、键盘聚焦或点击；说明浮层使用 Obsidian 语义颜色变量，兼容深浅主题。
- 问号按钮有可访问名称、展开状态和清晰焦点样式；点击页面其他位置或按 Escape 后关闭。

## 验证范围

- 单双引号方向错误、连续两三个引号、合法嵌套、多组对白。
- 保守与宽松补全的边界及互斥。
- YAML、代码块、行内代码、链接目标不被改写。
- CRLF 和重复执行保持稳定。
- 帮助说明只在两个补全选项出现，无常驻说明，并支持键盘和点击。

## 决策记录

- 选择上下文分析而不是全局正则替换，优先避免误改作者原文。
- 连续引号清理属于方向修复阶段，不新增第三个设置开关。
